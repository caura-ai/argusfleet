Semantic recall is table stakes. Governance is the difference.

Once a fleet of agents shares one memory, the question stops being “can the model find this?” and becomes “should this agent see it, which version is current, and who can prove where it came from?” We ran the same probes against MemClaw and Mem0. Here is what governed memory looks like when you measure it.

03

Why it matters for a fleet

Isolation you can prove

Separating customers or teams by an identifier only helps if the store enforces it on every path. MemClaw checks scope on retrieve-by-id, not just search — so a leaked or guessed ID isn’t a skeleton key.

One current answer

When two agents disagree, downstream agents need the resolved value — not both. Structural supersession means “active” retrieval returns the fact that won, with an auditable link to the one it replaced.

Governed sharing, not free-for-all

Fleet-scoped writes propagate to the agents entitled to them and no others, and re-homing memory is a privileged operation — visibility is policy, not a side effect of a shared key.

04

What we’ll say plainly

Fair-play notes

  • Mem0’s model is a design choice, not a bug. Its API key is the intended trust boundary; below it, user_id and run_id are query filters. That is fine for a single-tenant app — it is not sub-tenant governance, which is the axis measured here.
  • Mem0 has real strengths. In-scope recall was perfect (0 authorized-retrieval misses vs MemClaw’s handful), and its LLM extraction pipeline is genuinely good at distilling messy input.
  • Discovery filtering is imperfect on both. Semantic search surfaced ~44–46% of cross-scope probes on each platform — scoped retrieval, not search ranking, is what enforces the boundary.
  • MemClaw is our system. The harness (ArgusFleet) is open and runs against any wire-compatible service; every number here regenerates from committed traces. Run it yourself.
